**검토 방식:** ROADMAP 0.1.59(GPT 방향 검토 2회 반영, 사용자 확정)를 Claude가 구현. 자체 검토·자동 검사·폰 화면 확인. GPT 코드 리뷰 대기.

**이번에 건드린 화면:** 그리기(프리샷 인물 카드 머리 [📌 고정], 추출 전 확인 창, [↶ 추출 취소], 프리샷 복장 버튼 동작, 고정 외형 보기·[프로필 편집], 그리기 탭 안 프로필 편집기, [↓ 생성]), 프로필 탭(작성 중 내용 보호), 채팅 메시지 버튼.

설계와 다르거나 정해야 했던 점:
- 프로필 편집기는 카드 안이 아니라 **그리기 탭의 프로필 칸(새 프로필 만들기 자리)**에 열린다. 카드는 다시 그려질 때 안의 요소가 지워져서, 편집기를 카드 안에 두면 입력이 사라질 수 있다.
- [↶ 추출 취소]는 기존 비우기·가져오기 취소와 같은 규칙으로 **생성할 때도** 사라진다(ROADMAP 문안에 없던 경우).
- 고정 안 한 임시 인물: AI가 외형을 비워 보내면 기존 외형을 둔다(빈 값으로 덮지 않음).
- 카드 병합 충돌(ROADMAP ②): 지금 코드에는 두 카드를 합치는 경로가 없다. 임시→프로필 저장은 항상 새 프로필이고, 프로필 선택칸은 이미 있는 프로필로 바꾸는 것을 막는다. 그래서 묻는 창은 만들지 않았다.
- 추출 취소의 종류는 저장 형식(서버와 공용)을 바꾸지 않도록 안내 문구(`label`)로 구분한다.

**추가·정리한 기능**

- 모든 이력 그림에서 **챗샷으로 보내기 / 프리샷으로 보내기**를 제공한다. 챗샷은 현재 열린 채팅의 작업으로 가져오며 채팅이 없으면 이유와 함께 비활성화한다. 다른 채팅 그림 안내를 표시하고, 다른 채팅·프리샷을 챗샷으로 가져오면 대상은 최신 메시지로 초기화한다. 외부 메시지 source·후보 연결은 현재 채팅에 재사용하지 않는다. 원본 result의 소속·출처는 유지하고 새 생성은 목적지의 작업 키에 저장한다. 가져오기 자체는 AI/NAI를 호출하지 않는다. 덮어쓴 작업은 기존 작업 되돌리기로 복구한다. 모드 전환 대기 중 작업·채팅이 바뀌면 가져오기를 취소한다.
- 이력 확대 보기: **이전/다음·좌우 방향키·화면 맞춤 상태의 모바일 스와이프**, 현재 위치/전체 결과 수. 첫/끝에서 비활성화하며 순환하지 않는다. 열 때의 범위·채팅 필터·서버 정렬을 캡처하고 끝 두 장부터 다음 20개 기록을 미리 요청한다. PNG 전체 선로딩은 하지 않는다. 중복 페이지 요청을 합치고 오류 시 다음으로 재시도한다. 삭제는 진행 중 페이지 조회를 기다리고 커서를 보정한다. 확대 팬·핀치·핀치 후 남은 손가락으로는 넘기지 않는다. 프롬프트·seed·저장/삭제 대상·스킨·확대 위치는 그림마다 갱신한다. 결과 미리보기와 채팅 첨부는 기존 단일 그림 보기다.

## 이후 업데이트·교차 리뷰 작성 규칙

이 파일은 **NAIce Shot 저장소에 두는 UI·서버 공통 기록**이다. GPT와 Claude는 작업 전에 최신 항목과 미해결 문제를 읽고, 구현·리뷰·수정 후 관련 항목을 함께 갱신한다. 서버만 바뀌는 경우에도 서버 버전·저장소·커밋을 명시한다.

- 최신 버전의 항목을 위 버전 기록보다 앞에 넣는다. 같은 버전의 후속 리뷰는 그 항목에 덧붙인다. 이전 기록은 보존한다.
- 버전, 날짜, UI/서버 범위, 대상 커밋, 변경 요약, 검토자·검토 방식, 발견 문제, 해결 방법, 테스트 결과와 미확인 범위를 남긴다. 커밋 해시가 정해지지 않았다면 “미커밋”이라고 적고, 확정 후 실제 해시를 연결한다.
- 문제마다 고유 ID를 부여한다. **P1:** 데이터 유실·채팅 혼입·중대한 보안 문제 등 우선 해결할 결함. **P2:** 주요 동작 실패·잘못된 결과 등 기능 결함. **P3:** 경미한 동작·사용성·유지보수 문제. 등급과 함께 발생 조건·영향·근거를 적는다.
- 상태는 **미해결 / 수정됨·재검증 대기 / 해결됨 / 보류 / 재현 못 함**을 구분한다. 수정한 문제는 원래 ID, 수정 버전·커밋, 해결 방법, 재검증 결과를 연결한다. 다른 버전에서 해결해도 원래 발견 기록을 지우지 않는다.
- “문제 없음”, “통과”, “해결됨”은 실제 확인한 범위에만 사용한다. 정적 검토, 자동 테스트, 실제 기기·환경 확인을 구분한다. 테스트를 실행하지 않았다면 이유와 함께 **미실행**으로 적고, 이전 버전 결과를 새 결과처럼 쓰지 않는다.
- 같은 변경·테스트 설명을 여러 번 복사하지 않는다. 기존 문제 ID, 커밋, 검사 보고서로 연결하고 새 사실만 덧붙인다.
- 비밀 키, 실제 대화·캐릭터 설정, 개인 이름·이메일·PC 경로는 기록하지 않는다. 재현 예시는 중립적인 모의 데이터를 사용한다.
- **남은 계획과 넘겨줄 사항은 [docs/ROADMAP.md](ROADMAP.md)에 있다.** 작업을 맡기 전에 읽는다.
- **UI를 고치기 전에 [docs/DESIGN.md](DESIGN.md)를 읽는다.** 강조 단계·버튼 묶음·고정 배치·테마 규칙을 지키고, `tests/skins-lint.test.mjs`와 `tests/browser-v0149.mjs`를 돌린다. 리뷰 항목에 "이번에 건드린 화면"을 한 줄 적는다.
- `README.md`는 설치·사용·문제 해결 안내로 유지한다. 개발 판단·리뷰 지적·수정 추적은 이 파일에 기록하고, 세부 검사 자료는 `TEST-REPORT.md`에 연결한다.

### 개발 검사 실행

```bash
git clone https://github.com/Near7707/NAIce-Shot
git clone https://github.com/Near7707/NAIce-Shot-Server
cd NAIce-Shot
npm test
cd ../NAIce-Shot-Server
npm test
```

UI의 서버 연동 검사는 나란히 둔 `NAIce-Shot-Server` 또는 `NAICE_SERVER_DIR`을 찾는다. 서버가 없어서 건너뛴 검사는 반드시 결과에 표시한다. 브라우저 검사는 별도로 Playwright·Chromium 환경에서 실행하고, 무엇을 실제 실행했는지 보고서에 남긴다.

UI가 의존하는 서버 동작이 바뀌면 `compat.mjs`의 `MIN_SERVER_VERSION`과 `REQUIRED_SERVER_FEATURES`를 확인한다. 서버가 더 새 UI를 요구하면 서버 `handlers.mjs`의 `MIN_CLIENT_VERSION`을 확인한다.
