# NAIce Shot 남은 계획과 넘겨주기

이 문서는 Claude와 GPT가 번갈아 작업할 때 같은 결정을 보게 하려는 기록이다. 작업 전에 이 문서, [DESIGN.md](DESIGN.md), [REVIEW.md](REVIEW.md)의 규칙을 읽는다. 결정이 바뀌면 이 문서를 먼저 고친다.

## 작업 규칙 (모든 버전 공통)

- **"시작해" 전에는 만들지 않는다.** 설계 논의 중에는 시안·제안만 한다.
- 작업 전 `git pull`. **한 버전은 한 곳에서만 만든다.** 만든 쪽이 아닌 쪽이 리뷰한다.
- 커밋 작성자는 `Near7707 <338649039+Near7707@users.noreply.github.com>`. AI 도구는 공동 작성자 줄로만 적는다.
- 레포(README·예시·테스트·커밋 메시지)에는 **지어낸 이름만** 쓴다(Mira, Leo, Kai, Robin …). 사용자의 실제 캐릭터·이야기 이름·대사·스크린샷은 넣지 않는다.
- 릴리스마다 버전을 올리고(`core.mjs` VERSION, `manifest.json`, `package.json`), CHANGELOG에 **extension only** 또는 **extension + server**를 적는다. 서버가 바뀌면 순서: 서버 업데이트 → 실리태번 재시작 → 확장 업데이트 → 새로고침.
- UI를 고치면 `tests/skins-lint.test.mjs`, `tests/browser-v0149.mjs`를 꼭 돌린다. `npm test`는 서버 레포를 옆에 클론해 둬야 한다.
- 올리기 전 바뀐 부분에서 키·이메일·내 컴퓨터 경로·실제 캐릭터 이름을 점검한다. 비밀 값은 출력하지 않는다.
- REVIEW.md에 버전·커밋·발견 문제(ID, P1~P3)·상태·"이번에 건드린 화면"을 기록한다. 커밋 전에는 "미커밋", 커밋 후 해시로 바꾼다.

### 0.1.51 — 메시지로 가기 (3-1) · 끝남 (확장만, b2f7e27)
- 이력 카드 ⋯ 메뉴 맨 아래(구분선 아래)와 크게 보기 화면에 둔다.
- **만든 메시지와 넣은 메시지가 같으면 한 줄** [메시지로 가기], 설명 "#12 · 이 그림을 만들고 넣은 메시지". **다르면 두 줄** [넣은 메시지로 가기 #14] / [만든 메시지로 가기 #12]. 크게 보기에서는 다를 때 누르면 둘 중 고른다.
- 지금 채팅 안: 패널을 닫고 그 메시지로 스크롤, 2초 동안 테두리 강조. 화면에 안 불러온 옛 메시지는 더 불러와서 찾는다.
- 다른 채팅: 이동 전에 한 번 확인 창("○○ 채팅으로 이동할까요? 그리기창 작업은 저장돼 있어요").
- 메시지가 지워졌으면 이동하지 않고 안내. 내용이 바뀌었거나 다른 스와이프면 이동하고 그렇다고 알린다.
- 연결된 메시지가 없는 그림(프리샷, 옛 그림, 추출 없이 만든 그림)은 버튼을 흐리게 하고 이유 한 줄.
- 같은 위치 찾기를 쓰는 **본문에 넣기**: 만든 메시지를 못 찾으면 말없이 맨 마지막 메시지에 넣지 말고 넣을 메시지를 고르게 한다.

### 0.1.55 — 설정·옷·프로필 다듬기 · GPT에게 맡겨도 됨 (전에 0.1.52~0.1.54로 적었던 계획)
**① 설정 → 공통 이미지 프리셋**
- [불러오기]는 맨 위. 짧은 칸은 폰에서도 두 칸씩: 모델·이미지 크기 / 스텝·Guidance / Seed·CFG Rescale.
- 저장 이름과 버튼은 **NAI 생성 설정 맨 아래 상자**("프리셋으로 저장")로 옮긴다. 값을 채운 자리에서 바로 저장.
- 버튼은 **현재 선택 기준**:
  - 프리셋을 고른 상태: 주 버튼 **[변경 저장 · 이름]**(확인 창), 옆에 [새 프리셋으로 저장], [선택 프리셋 삭제].
  - [+ 새 프리셋 만들기]: 모든 칸을 비우고 선택을 푼다(기존 항목을 덮어쓰지 못하게). 이때는 [새 프리셋으로 저장]만.
  - 이름은 한 줄, 길면 "…"(전체 이름은 title).
  - DESIGN.md의 "덮어쓰기는 주 버튼이 아니다"를 "선택된 프리셋의 변경 저장은 확인 창과 함께 주 버튼"으로 고친다.

**② 그리기 → 인물 카드 옷**
- [지금 옷을 기본으로]·[옷장에 저장]을 "이번 그림" 묶음 안 **"이 복장을"** 줄로 옮긴다: [이 채팅 기본으로] / [옷장에 저장]. "이 채팅에서" 묶음은 채팅 기본 복장 선택·안내·잠금만.
- 입력칸 이름 "복장" → **"이번 그림 복장"**.
- 잠금 설명(그대로 쓸 것): "켜면 AI가 메시지에서 새 옷을 찾아도 그림에 적용하지 않아요. 채팅 기본 복장을 계속 입고, 채팅 기본 복장이 없으면 프로필 기본 복장을 입어요. '이번 그림 복장'에서 직접 고친 옷은 그대로 적용돼요."

**③ 그리기 → 고정 외형 · 전용 태그**
- 펼치면 고정 외형, 전용 Positive, 전용 Negative를 고칠 수 있다. 안내: "프로필을 고쳐요. 다른 장면·채팅의 그림에도 적용돼요."
- 버튼 두 개를 **같은 크기로 작게** 나란히(주 버튼처럼 한 줄 전체 X): [프로필 업데이트](확인 창: "○○ 프로필의 외형을 덮어써요. 다른 채팅의 그림에도 적용돼요.") / [새 프로필로 저장](복사본 프로필을 만들고 이 장면 인물에 연결).
- 외형 옷장(외형 여러 벌)은 만들지 않는다.

시안: 사용자와 확인한 폰 화면(설정 프리셋, 옷 버튼, 고정 외형). 레포에는 넣지 않는다.

### 3-2 — 메시지 배지·그림 모음 · 설계부터
메시지에 그 메시지에서 만든 그림 수 배지, 메시지별 그림 모음. 서버에 개수 조회가 필요할 수 있어 **UI + 서버**가 될 수 있다. 시안 확정 전 구현하지 않는다.

### 3-3 — 그림마다 넣는 위치
그림별 넣는 위치(메시지 위/아래 등). 우선순위: 그림 설정 > 채팅 설정 > 전체 설정.

### 설명서 (패널 안)
9개 장, 검색, 뒤로 가기. 꼭 넣을 것:
- 클린 PNG가 메타데이터를 지우는 방식(다시 인코딩, EXIF는 메타데이터의 한 종류, 투명 부분 불투명, 그림 안 글자는 남음)
- 파일 이름이 안전한 이유(무작위 ID, 이름·채팅 내용 없음)
- 확장·서버 업데이트 방법(위 순서)
- 이력 보기 범위는 그리기 모드와 따로 고른다
